# Tinkle SDK for Android

Handwritten Android packaging, initialization, and final-AAR consumer tests for
the shared [Tinkle Rust engine](https://github.com/tinkle-org/libtinkle).
Apache-2.0; see [LICENSE](LICENSE).

## Source and distribution layout

This directory is the canonical Kotlin SDK source package in libtinkle. The
downstream distribution is `tinkle-org/tinkle-sdk-kotlin`, with Maven coordinate
`com.github.tinkle-org:tinkle-sdk-kotlin:<tag>` and JitPack repository
`https://jitpack.io`. Its root Android library is the only public Maven component.
The sample is included only for `:sample:*` tasks or `-PincludeSample=true`.

Generated Kotlin remains canonical at
`bindings/kotlin/com/tinkle/sdk/tinkle_ffi.kt` in the repository root. It is
intentionally absent here. Root `scripts/sdk-ci.py` stages the matching binding
into `src/main/kotlin/com/tinkle/sdk/tinkle_ffi.kt` in a **disposable package
copy**, together with the candidate/release metadata. Build and test that copy;
do not copy generated sources or native build outputs back into this directory.
Root automation owns Rust builds, release provenance, and downstream promotion.

## Install and initialize

```kotlin
// settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        maven("https://jitpack.io") {
            content { includeGroup("com.github.tinkle-org") }
        }
    }
}

// app/build.gradle.kts
dependencies {
    implementation("com.github.tinkle-org:tinkle-sdk-kotlin:<tag>")
}
```

Requirements: Android minSdk **24**, compileSdk **36**, JDK **17**. The sample
targets API **36**. All four ABIs are mandatory: `arm64-v8a`, `armeabi-v7a`,
`x86_64`, and `x86`. The POM/Gradle metadata carry **JNA 5.18.1 as an Android AAR**,
Kotlin stdlib, and **coroutines 1.10.2** transitively. JNA's bundled
`libjnidispatch.so` is part of the 16 KB runtime contract; retain the Android AAR.

```kotlin
import com.tinkle.sdk.TinkleSdk

// Application.onCreate(), before any generated API calls:
TinkleSdk.initialize()
```

Initialization is thread-safe and idempotent. It calls
`uniffiEnsureInitialized()` before `tinkleFfiInit()` so UniFFI **0.32.2** verifies
the native contract/function checksums and registers foreign callbacks. Release
generated object handles with `close()`/`destroy()` when their owner finishes.

Rust owns protocol handling, subscriptions, per-target journals, reconciliation,
and persistence. Prefer `SqliteStorage.openAsync(path)` with
`TinkleClient.newSqlite(config, credential, storage)` for the shared native
database. SQLite commits cache changes and journal positions atomically. Stop
clients before `clearPrincipal`, and reopen/reconcile before resuming them.
Alternatively implement the asynchronous `FfiCursorStore` callbacks
`loadJournal`, `saveJournal`, `removeTarget`, and `clearPrincipal`. Journal keys
are `target:user:<id>` and `target:room:<id>`, scoped by `user:<principal-id>`;
positions are signed `Long`, with zero as the initial position. The in-memory
Rust store is for ephemeral sessions/testing.

## Build a staged package

The package uses **Gradle 8.13**, **AGP 8.13.0**, and **Kotlin 2.3.0**. It consumes
prebuilt Rust artifacts and never invokes Cargo or generates bindings. The
wrapper was generated by Gradle's `wrapper` task. Its JAR SHA256 is
`81a82aaea5abcc8ff68b3dfcb58b3c3c429378efd98e7433460610fecd7ae45f`;
`gradle-wrapper.properties` also pins the distribution SHA256.

Run these commands from the disposable package root after staging:

```sh
bash gradlew verifySdkArtifacts assembleRelease \
  -PsdkArtifactDir=/absolute/path/to/artifacts \
  -PsdkAndroidSha256=<android-zip-sha256> \
  -PsdkKotlinBindingsSha256=<kotlin-zip-sha256>
```

The artifact directory must contain `android-native-libraries.zip` with exactly
`jniLibs/<abi>/libtinkle_ffi.so` for all four ABIs, and `kotlin-bindings.zip` with
`com/tinkle/sdk/tinkle_ffi.kt`. Environment equivalents are
`TINKLE_SDK_ARTIFACT_DIR`, `TINKLE_SDK_ANDROID_SHA256`, and
`TINKLE_SDK_KOTLIN_BINDINGS_SHA256`. The existing single-archive CI adapter also
accepts `TINKLE_SDK_NATIVE_ARCHIVE` plus `TINKLE_SDK_NATIVE_SHA256`, requiring the
canonical native ZIP name and a sibling Kotlin ZIP.

`prepareSdkArtifacts` verifies hashes before opening archives, rejects unsafe or
unexpected paths and incomplete ABI sets, and compares the Kotlin archive
byte-for-byte with the staged binding. Only verified native output enters
`build/generated/sdk/jniLibs`. Extraction never writes repository sources.

Release packages include `sdk-artifact.json`: the complete schema-1 manifest,
exact source revision, `source_repository: "tinkle-org/libtinkle"`,
`source_tag: "tinkle-ffi-v<version>"`, and `ios`, `swift_bindings`, `android`, and
`kotlin_bindings` entries containing canonical filename, HTTPS URL, and SHA256.
The manifest's hashes are authoritative, including when local archives are used.
The AAR retains it at `assets/tinkle-sdk/sdk-artifact.json`. Downloads restrict
redirects to GitHub release hosts. Manifest-free bootstrap is restricted to
`0.0.0-local`; JitPack requires a release manifest and matching generated binding.
`jitpack.yml` verifies the artifacts and publishes the single release component.

## Verification

```sh
# Independent archive/provenance rejection tests; no native runtime needed.
bash gradlew -p buildSrc test
python3 -m unittest discover -s tests -v

# Build the exact final AAR from staged inputs, then consume those bytes.
bash gradlew assembleRelease
bash gradlew :sample:connectedDebugAndroidTest \
  -PtinkleSdkTestAar=/absolute/path/to/tinkle-sdk-kotlin-release.aar

# Installed release/R8, all bundled ELF files, and APK ZIP alignment proof.
bash scripts/verify-consumer.sh --core /absolute/path/to/libtinkle \
  --aar /absolute/path/to/tinkle-sdk-kotlin-release.aar --page-size 16384
# Repeat with --page-size 4096 on a regular-page device.

# Optional metadata/transitive-dependency proof via local Maven publication.
bash gradlew publishReleasePublicationToSmokeRepository
bash gradlew :sample:connectedDebugAndroidTest
```

Keep the staged artifact properties/environment available during producer tasks.
The file-AAR sample adapter explicitly supplies JNA and coroutines because an AAR
alone has no dependency metadata. The sample never depends on the library source
project. Both smoke build types enable R8 optimization/obfuscation and local
debug signing; even the debug smoke variant is non-debuggable. Instrumentation
startup keeps are sample-only. Shipped consumer rules preserve JNA native names,
reflected structures, and callback ABI; only four desktop AWT types are
suppressed, without disabling shrinking or checksum validation.

The installed target APK initializes twice, constructs/releases a Rust store,
then connects a real Rust client to a test-only loopback gateway. It proves
suspending Kotlin journal loads/saves from Rust, principal/target isolation,
successful checkpoint events, and typed foreign load/save failure diagnostics.
Empty pages cannot fabricate journal progress. A Rust-owned on-disk SQLite
smoke commits a real deletion journal page, closes/reopens native handles,
resumes from the persisted cursor, round-trips user/chat protobufs, rejects a
mismatched embedded ID, and verifies durable principal-scoped clearing.

Run API 36 lanes on regular 4 KB and 16 KB devices, plus minimum-OS API 24 where
available. The 16 KB helper disables compatibility mode and checks read-back,
runs installed release instrumentation, calls root `scripts/verify-android.sh`
on every final APK (including JNA), checks `zipalign -c -P 16 -v 4`, and rejects
enabled page-size compatibility in the merged manifest. A compile or AAR assembly
alone is not runtime proof; report unavailable runtime lanes explicitly.
